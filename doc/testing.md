# 测试与校准

## 单元测试

```bash
./gradlew :app:testDebugUnitTest
```

12 个 JUnit 用例覆盖 `CadenceEstimator`（纯 Kotlin，JVM 直接跑，不需要模拟器）：

- **精度扫描**：80/100/120/140/160 spm 合成信号，逐点报告误差
- **谐波校正**：手持模式正确降八度，口袋模式不误降
- **弱信号**：口袋幅度（0.6 m/s²）下精度不变
- **门控**：静止、随机晃动、非节律信号正确拒绝

合成信号模型：`9.8 + 1.5·sin(2πft) + 0.3·sin(4πft) + 噪声 + ±15% 采样间隔抖动`，即重力 + 基频 + 二次谐波 + 噪声 + 不均匀采样——刻意模拟真实传感器的恶劣条件。

当前精度报告（`printAccuracyReport` 用例直接打印）：

```
 true_spm  est_spm   err  prominence    cv
    80.0    80.64  0.64       0.66 0.011
   100.0   100.00  0.00       0.62 0.015
   120.0   119.40  0.60       0.55 0.021
   140.0   140.59  0.59       0.51 0.027
   160.0   159.33  0.67       0.49 0.033

```

门限裕度：prominence 实得最低 0.49 vs 门限 0.30，留足了真机噪声的空间。

**改任何参数后跑一次测试即可量化影响**——这是离线调参的核心工作流，比在真机上盲调高效一个数量级。

## 真值获取（真机校准）

按成本从低到高：

1. **节拍器**（推荐，零成本）：手机装个节拍器 App，设 100/110/120/130/140 BPM 跟着节奏走，真值已知且精确
2. **视频慢放**：拍侧面走路视频，慢放人工数步数 ÷ 时间
3. 跑台定速（有条件）：速度已知时可交叉验证步频 × 步幅
4. 足底压力鞋垫（实验室级）

## 真机验证清单

- [ ] 正常摆臂行走：读数稳定性、与节拍器真值的误差
- [ ] 低头盯屏幕（手臂僵住）：应显示「未检测到」而不是错误读数
- [ ] 口袋里上下楼梯：幅度大节律性好，应稳过门控
- [ ] 乘车（公交/地铁）：应拒绝输出（CV + 突出度判据）
- [ ] 锁屏后台记录 30 分钟：会话完整、耗电可接受
- [ ] 国产 ROM 后台白名单引导（小米/华为/OPPO）
- [ ] 至少 3–5 个机型：低端机传感器噪声明显更大

## 指标定义

- **MAE**（spm）：主指标，分速度档（慢走 ~80 / 常速 ~110 / 快走 ~140 spm）统计
- **Bland-Altman 一致性区间**：看系统性偏差
- **误差矩阵**：放置位置 × 速度 二维，对外不承诺统一精度，如实公布差异
