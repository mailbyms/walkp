# 算法详解

本文档解释步频估计的完整信号处理链路，以及每个设计决策背后的原因。核心代码在 `app/src/main/java/com/walkp/cadence/dsp/`。

## 信号管线

```
加速度计事件 (event.timestamp, x, y, z)
  → 按时间戳线性重采样到固定 50 Hz
  → 三轴取模值 sqrt(x²+y²+z²)
  → 窗内去均值 + 去线性趋势
  → 4 s 汉宁窗 + 256 点 FFT（每 250 ms 分析一次）
  → 1–3 Hz (60–180 spm) 内取幅度最大 bin
  → 抛物线插值细化主峰频率
  → 谐波校正（仅手持模式）
  → 与时域峰值检测结果融合 + 指数平滑输出
```

## 三个容易踩错的坑

### 1. 必须按时间戳重采样

Android 的实际采样间隔不均匀，且与注册值有偏差（不同机型差异明显）。直接用「事件序号 × 标称间隔」当时间轴做 FFT，会引入系统性的频率偏差。正确做法是读 `event.timestamp`（纳秒，SystemClock 族时钟），线性插值重采样到固定 50 Hz 网格。

### 2. 先取模值，再去重力——顺序不能反

重力（≈9.8 m/s²）在模值中占主导：`|g + a| ≈ g + a·ĝ`，垂直方向的步行加速度分量被完整保留在模值里，且**与手机姿态无关**（横拿竖拿都一样）。

如果反过来——先把重力从各轴减掉再取模——信号会被整流（全波整流效应），负半周翻到正半周，主频直接**翻倍成 2× 步频**，结果全错。这是步频/计步算法最常见的新手错误。

### 3. 模值主频 = 步频，单轴不一定

垂直方向（或模值）信号每一步一个峰，主频 = 步频。但**前后方向单轴**信号一个步态周期（左右脚各一步）才一个完整摆动，主频 = 步频的一半。只取单轴分量算出来的步频会差一倍。

口袋场景的补充：手机贴单侧大腿，肢体摆动主频是步态周期频率（步频/2），但腿的钟摆式摆动垂直位移 ∝ θ²，基频翻倍回步频；而模值里重力主导、投影的正是垂直分量——所以**模值主频 = 步频，手持和口袋通用**。两种位置的真实差异只在信号幅度（口袋明显更小）与谐波丰富度（口袋接近正弦波）。

## 频域主算法

- **采样率**：50 Hz。步行主频 1–2.5 Hz，奈奎斯特 25 Hz 足以保留 4 次谐波
- **窗长**：4 s。频率分辨率 0.25 Hz = 15 spm，粒度太粗，必须配合插值
- **窗函数**：汉宁窗，压旁瓣防相邻峰泄漏
- **主峰细化**：抛物线插值。对主峰及其左右相邻 bin 的幅度（对数域更佳）拟合抛物线取顶点，亚 bin 精度。不插值的话读数只能以 15 spm 一档跳变，完全不可用
- **搜索范围**：1–3 Hz（60–180 spm），覆盖慢走到快走

## 谐波校正（仅手持）

手持时手臂摆动叠加多余动作，频谱谐波丰富。当人走得很快（步频 > 2.4 Hz ≈ 144 spm）时，二次谐波可能幅度超过基频，直接取最大峰会报出两倍的错误步频。

校正规则：若主峰 > 2.4 Hz，检查其半频处是否存在幅度 ≥ 50% 的子峰，存在则降八度取半频。

口袋模式信号接近正弦、谐波少，**禁用**该校正（否则可能把真实的快步走错误减半）。单元测试 `pocketModeSkipsHarmonicCorrection` 直接验证了两种模式的行为差异。

## 时域辅算法

自适应阈值峰值检测 + 250 ms 不应期（上限 240 spm），取最近 6–10 个峰间隔的**中位数**。延迟比频域低，用于即时反馈。

**融合策略**：频域与时域结果相差 < 8% 时输出频谱值（更稳）；差异大时标记「信号不稳定」而不是强行二选一——手持抖动、上下楼梯场景下这种保守策略体验明显更好。

输出再做一阶指数平滑（手持 α=0.35，口袋 α=0.40），时间常数约 1–2 s。不过度平滑：步频本来就该随速度实时变化。

## 门控：在不在走路

三个条件同时满足才输出数值，否则显示「--」而不是 0：

| 判据 | 门限（手持/口袋） | 排除什么 |
|---|---|---|
| 窗内 RMS | 0.25–6.0 / 0.12–6.0 | 静止、剧烈晃动 |
| 主峰突出度 = 主峰能量 / 1–3 Hz 总能量 | ≥ 0.30 | 白噪声式随机晃动 |
| 峰间隔变异系数 CV = std/mean | ≤ 0.18 / 0.20 | 非节律性运动 |

第三条尤其有效：人走路是极其节律的运动，乘车颠簸、随手摇晃都过不了这关。交通工具还有 1–3 Hz 低频振动，但节律性差，CV 判据 + 突出度判据组合可以排除。

短暂停顿（< 1.5 s）保持上次读数，超过才进入等待态——避免路口等红灯时读数闪断。

## 手持 vs 口袋参数对照

| 参数 | 手持 | 口袋 | 原因 |
|---|---|---|---|
| MIN_RMS | 0.25 | 0.12 | 口袋里贴身，加速度幅度明显更小 |
| 谐波校正 | 启用 | 禁用 | 口袋信号接近正弦，谐波少 |
| MAX_CV | 0.18 | 0.20 | 口袋里手机会松动晃动 |
| smoothAlpha | 0.35 | 0.40 | 口袋信号噪声大，多平滑一点 |
